# Shorts Pipeline

Конвейер производства вертикальных шортсов: ссылка на видео → транскрипция →
поиск самостоятельных моментов → нарезка → монтаж → публикация на YouTube и в
Instagram.

```
ссылка ─▶ yt-dlp ─▶ whisper ─▶ LLM ─▶ ffmpeg (нарезка) ─▶ ffmpeg (монтаж) ─▶ YouTube / Instagram
             │          │         │                            │
             └── ffprobe└─ облако └─ Claude / OpenAI / Ollama   └─ маска, фильтр, заголовок,
                 + эвристика                                       зум, зеркало, баннер+хромакей
                 вшитого текста
```

## Что делает каждый модуль

| Стадия | Задача воркера | Что происходит |
| --- | --- | --- |
| Загрузка | `project.ingest` | yt-dlp скачивает исходник по ссылке — либо берётся готовый файл с диска, если источником указан путь; ffprobe снимает параметры, извлекается моно-аудио 16 кГц, эвристика проверяет наличие вшитого текста в кадре |
| Транскрипция | `project.transcribe` | faster-whisper локально на GPU; при неудаче — OpenAI Whisper или Deepgram |
| Анализ | `project.analyze` | Транскрипт режется на куски с нахлёстом и уходит в LLM; та возвращает моменты 15–45 с со списком диапазонов, немецким заголовком, описанием и хэштегами |
| Плоская нарезка | `project.chunk` | Замена двум стадиям выше: исходник режется на куски равной длины без распознавания речи и без модели. Включается `chunks.enabled` |
| Монтаж | `segment.render` | Нарезка с подгонкой границ к паузам между словами, затем фильтрограф ffmpeg |
| Публикация | `segment.publish` | YouTube Data API v3 (резюмируемая загрузка) и Instagram Reels — через Graph API или входом по логину и паролю. Куда именно уходит ролик, решает связь «аккаунт ↔ проект», а не пресет |

Порядок фильтров в монтаже:

```
скорость 1.01–1.05 → кадрирование в 9:16 → зеркало → зум → цвет/LUT
  → маска → баннер с вырезанным хромакеем → заголовок → субтитры
```

Он не случайный: зеркалить нужно **до** наложения нашего заголовка, иначе текст
окажется зеркальным; зум идёт после кадрирования, чтобы предсказуемо съедать
края; хромакей — до наложения баннера на кадр.

## Быстрый старт

```powershell
.\scripts\bootstrap.ps1
```

Скрипт найдёт подходящий Python, создаст `.venv`, поставит зависимости, скачает
ffmpeg в `tools\ffmpeg`, сгенерирует `.env` с ключом шифрования и установит
зависимости панели.

Затем впиши ключи в `.env` и запусти:

```powershell
.\scripts\run.ps1
```

Панель откроется на <http://localhost:5173>, документация API — на
<http://localhost:8000/docs>.

Для продакшена: `.\scripts\run.ps1 -Prod` соберёт панель и отдаст её тем же
сервером на порту 8000.

### Вручную, тремя терминалами

```powershell
# 1. API
.\.venv\Scripts\python.exe -m uvicorn app.main:app --port 8000
```

```powershell
# 2. Воркер (без него очередь стоит)
.\.venv\Scripts\python.exe -m app.queue.worker
```

```powershell
# 3. Панель
npm run dev
```

Первые две команды выполняются из каталога `server`, третья — из `web`.

## Настройка

Всё в `.env` (образец — `.env.example`).

### Обязательное

| Переменная | Зачем |
| --- | --- |
| `SHORTS_SECRET_KEY` | Шифрование токенов площадок. Генерируется bootstrap-скриптом. **При смене ключа аккаунты придётся подключить заново.** |

### Транскрипция

Локальный faster-whisper — по умолчанию, облако — как запасной вариант.

| Переменная | Значение по умолчанию |
| --- | --- |
| `SHORTS_WHISPER_MODEL` | `large-v3` |
| `SHORTS_WHISPER_DEVICE` | `cuda` (падает на CPU, если CUDA недоступна) |
| `SHORTS_WHISPER_COMPUTE_TYPE` | `float16` |
| `SHORTS_STT_FALLBACK` | `openai` (или `deepgram`, или `none`) |

`large-v3` на RTX 3060 занимает около 3 ГБ видеопамяти и обрабатывает час записи
за 4–8 минут. Если памяти мало — возьми `medium` или `distil-large-v3`.

Веса скачиваются при первом запуске транскрипции (`large-v3` — около 3 ГБ) и
кладутся в `storage/models`. Первая задача поэтому идёт заметно дольше
последующих.

> **Python 3.13+ не подойдёт для локальной транскрипции**: колёс `ctranslate2`
> под него ещё нет. Bootstrap это заметит и оставит только облачный путь.

### Языковая модель

| Переменная | Значение |
| --- | --- |
| `SHORTS_LLM_PROVIDER` | `anthropic` \| `openai` \| `ollama` |
| `SHORTS_LLM_MODEL` | `claude-opus-5` |
| `ANTHROPIC_API_KEY` | ключ Claude API |

Провайдер выбирается один для всей системы; переключается перезапуском сервера.
Системный промпт кэшируется между кусками транскрипта, поэтому длинное видео
обходится заметно дешевле, чем кажется по объёму текста.

### Публикация

**YouTube.** В Google Cloud Console включи *YouTube Data API v3*, создай
OAuth-клиент типа **Desktop app** и впиши `YOUTUBE_CLIENT_ID` и
`YOUTUBE_CLIENT_SECRET`. Дальше — кнопка «Подключить YouTube» в панели.

Дневная квота проекта — 10 000 единиц, одна загрузка стоит 1600. Это **примерно
шесть роликов в сутки**. Квота обнуляется в полночь по тихоокеанскому времени;
увеличение запрашивается через форму в Cloud Console.

**Instagram.** Два способа подключить аккаунт, кнопка «Подключить Instagram» в
панели предлагает оба.

*Логин и пароль* — обычный аккаунт, ничего настраивать не нужно. Клиент
представляется мобильным приложением (`instagrapi`), ролик уходит файлом,
публичный адрес сервера не требуется. Пароль хранится в базе зашифрованным
`SHORTS_SECRET_KEY`: без него не восстановить сессию, когда Instagram её
сбросит. Если включена двухфакторная аутентификация, панель спросит код; можно
сохранить её секрет (base32) — тогда коды генерируются сами.

Instagram автоматизацию не одобряет, и за это придётся платить вниманием:

- публикуй единицы роликов в сутки и держи паузы между ними;
- не меняй адрес выхода в сеть от запуска к запуску (либо всегда один прокси);
- сессия сохраняется и переиспользуется — каждый вход по паролю Instagram
  считает подключением нового устройства;
- если Instagram потребует подтвердить вход, панель этого сделать не сможет —
  см. «Instagram требует подтвердить вход» ниже.

*Graph API* — официальный путь. Нужен Business или Creator-аккаунт,
привязанный к странице Facebook, и приложение Meta с правами `instagram_basic`,
`instagram_content_publish`, `pages_show_list`, `pages_read_engagement`. Meta не
пропускает OAuth-редирект на localhost, поэтому токен вставляется вручную:
возьми User Access Token в Graph API Explorer, вставь в панели — сервер сам
обменяет его на 60-дневный и найдёт привязанные аккаунты.

У этого пути своё ограничение: **Instagram не принимает файл напрямую**, он
скачивает ролик по публичному URL. Поэтому нужен `SHORTS_PUBLIC_BASE_URL` —
адрес, по которому сервер доступен из интернета (реверс-прокси или туннель вида
`cloudflared tunnel --url http://localhost:8000`). Ссылка на файл подписывается,
так что перебрать чужие ролики по ней нельзя.

Лимит Instagram — 25 публикаций за 24 часа на аккаунт.

### Публикация из консоли

`scripts/ig_publish.py` публикует готовый файл в Reels, минуя базу, очередь и
панель — удобно для разовой отправки и для первого входа, когда Instagram
требует подтверждение.

```powershell
.\.venv\Scripts\python.exe scripts\ig_publish.py --check
.\.venv\Scripts\python.exe scripts\ig_publish.py storage\renders\clip.mp4 --caption "Текст"
.\.venv\Scripts\python.exe scripts\ig_publish.py clip1.mp4 clip2.mp4 --caption-file text.txt --delay 900
```

Логин и пароль берутся из `.env` (`INSTAGRAM_USERNAME`, `INSTAGRAM_PASSWORD`,
`INSTAGRAM_TOTP_SEED`, `INSTAGRAM_PROXY`); если пароля там нет, скрипт спросит
его сам. Аргументом командной строки пароль не принимается: аргументы видны в
списке процессов и оседают в истории оболочки.

Сессия кладётся в `storage/instagram/<логин>.json` — этот каталог общий для
скрипта и панели, поэтому вход, который пришлось подтверждать в консоли,
годится и панели. Там же хранятся идентификаторы «устройства», и они
сохраняются даже после неудачной попытки: Instagram привязывает подтверждение
входа именно к устройству, и повтор с новыми идентификаторами упёрся бы в новую
проверку. По этой же причине `--relogin` сбрасывает авторизацию, но устройство
оставляет прежним.

### Instagram требует подтвердить вход

Ответ вида «Manual verification required via Instagram native challenge flow»
означает, что Instagram не пустил вход по паролю и ждёт проверку, которую из
кода не пройти.

Важное: **подтверждать при этом чаще всего нечего**. Уведомление на телефон не
приходит, письма нет, в «Активности входа» пусто — Instagram не заводит
настоящую проверку для клиента, которого не узнал, а просто закрывает дверь.
Искать её по приложению и почте бесполезно, время потратишь зря.

Рабочий путь — **войти по `sessionid`**: проверку проходит браузер, а сюда
попадает уже готовая сессия.

1. Войди на instagram.com в браузере (Chrome, Edge, Yandex, Brave — любой).
2. `F12` → вкладка **Application** (в русском интерфейсе «Приложение») →
   слева **Storage → Cookies** → `https://www.instagram.com`.
3. Найди строку `sessionid` и скопируй **значение из столбца Value** — вид
   `71234567890%3AAbCd…`. Через консоль (`document.cookie`) её не видно: кука
   помечена HttpOnly, так и задумано.
4. Дальше либо в панели — кнопка «Войти по sessionid» в форме подключения,
   либо:

```powershell
.\.venv\Scripts\python.exe scripts\ig_publish.py --sessionid --check
```

Скрипт спросит куку скрытым вводом (в историю оболочки она не попадёт), логин и
пароль при этом не нужны.

После удачного входа сессия ложится в `storage/instagram/`, и панель возьмёт её
же: подключай аккаунт в разделе «Аккаунты» тем же логином и паролем — пароль
там пригодится позже, а вход пройдёт по сохранённой сессии, без нового запроса
проверки.

Плата за этот способ: сессия умрёт, если выйти из аккаунта в том же браузере
(просто закрыть вкладку можно), и продлить её без пароля нечем. Если ходишь
через прокси — в браузер заходи с того же адреса, иначе Instagram увидит скачок
IP и потребует проверку уже на саму сессию.

Автоматически достать куку из браузера нельзя: Chrome, Edge, Yandex и Brave
шифруют хранилище кук привязкой к приложению (App-Bound Encryption). Это та же
стена, из-за которой yt-dlp на Windows умеет читать куки только из Firefox.

## Пресеты и переопределения

Настройки применяются слоями:

```
значения по умолчанию → пресет → настройки проекта → настройки фрагмента
```

Каждый слой хранит только отличия, поэтому изменение пресета подхватывается
всеми проектами, где не задано обратное. В панели у проекта и у каждого
фрагмента есть кнопка настроек: там добавляется раздел целиком (со значениями
из пресета), а дальше правятся отдельные поля.

Форма настроек строится по структуре конфига автоматически — новый ключ на
бэкенде сразу появляется в панели.

## Модули монтажа

| Модуль | Настройка | Комментарий |
| --- | --- | --- |
| Скорость | `edit.speed` | 1.01–1.05, по умолчанию случайное значение на каждый фрагмент — ролики отличаются друг от друга |
| Кадрирование | `edit.framing` | `crop` (обрезка по фокусу), `blur_pad` (размытый фон), `fit` (чёрные поля) |
| Зум | `edit.zoom` | статический или Ken Burns |
| Зеркало | `edit.mirror` | по умолчанию срабатывает, **только если в кадре нет текста** |
| Цвет | `edit.color` | LUT-файл плюс яркость/контраст/насыщенность/резкость/виньетка |
| Маска | `edit.mask` | PNG с альфой или видео поверх кадра, режимы наложения |
| Баннер | `edit.banner` | оверлей с вырезанием хромакея и подавлением зелёного ореола |
| Заголовок | `edit.title` | немецкий заголовок из фрагмента; по умолчанию рисуется, только если в исходнике заголовка нет |
| Субтитры | `edit.subtitles` | ASS из пословных таймкодов, выжигаются в кадр |

### Про определение текста в кадре

Флаг «есть ли вшитые субтитры» вычисляется эвристикой: из полосы кадра берутся
кадры, считается плотность вертикальных границ (у букв их много) и то,
насколько полоса меняется со временем. Статичный логотип даёт плотность без
изменчивости, субтитры — и то и другое.

Это **оценка, а не факт**. При низкой уверенности сервер честно ставит «не
определено», и решение остаётся за человеком — в карточке проекта есть
переключатель. От этого флага зависит зеркалирование, так что при сомнениях
лучше выставить его вручную.

## Структура

```
server/app/
  config.py            настройки из .env
  models.py            схема БД
  db.py                подключение, SQLite в режиме WAL
  queue/               очередь задач и воркер
  pipeline/
    config_schema.py   полный конфиг со значениями по умолчанию
    stages/            ingest, transcribe, analyze, chunk, edit, publish
  providers/
    stt/               faster-whisper, OpenAI, Deepgram
    llm/               Anthropic, OpenAI, Ollama
    publish/           YouTube, Instagram (Graph API и вход по паролю)
  media/               ffmpeg, ffprobe, фильтрограф, нарезка, субтитры, детектор текста
  api/                 роуты FastAPI и поток событий
web/src/               панель на React
```

Очередь работает поверх той же SQLite: воркер атомарно забирает задачу через
`UPDATE ... WHERE status='queued'`. Redis и Celery не нужны — на одной машине с
десятками задач в час это лишний слой, а на Windows Celery ещё и капризен.

## Диагностика

Страница «Диагностика» в панели показывает, что настроено: найден ли ffmpeg,
доступны ли провайдеры распознавания и LLM, задан ли публичный адрес, сколько
свободно на диске, что в очереди.

Типичные ситуации:

| Симптом | Причина |
| --- | --- |
| Очередь стоит, задачи в статусе «в очереди» | Не запущен воркер |
| «ffmpeg не найден» | Запусти `bootstrap.ps1` или задай `SHORTS_FFMPEG_PATH` |
| Транскрипция уходит в облако | `faster-whisper` не установился — проверь версию Python |
| Публикация в Instagram падает на контейнере | Не задан `SHORTS_PUBLIC_BASE_URL` или сервер недоступен снаружи (только Graph API) |
| Instagram «требует подтвердить вход» | Войди на instagram.com в браузере — проверка появится там; если не помогло, подключись по `sessionid` (см. «Публикация из консоли») |
| Instagram «временно ограничил действия» | Слишком часто публикуешь с одного аккаунта — пауза на несколько часов |
| YouTube отвечает «quota» | Исчерпаны 10 000 единиц в сутки |
| «не удалось расшифровать учётные данные» | Сменился `SHORTS_SECRET_KEY` — подключи аккаунты заново |

Полный лог каждой задачи — в панели, страница «Очередь» → кнопка «Лог».

## Правовая сторона

Инструмент скачивает чужие видео по ссылке и перезаливает нарезки. Это несёт
риски: условия использования YouTube запрещают загрузку без разрешения, а
авторские права на исходник остаются у автора. Работай со своим контентом или с
тем, на который у тебя есть права; при перезаливе чужого материала претензии
будут к владельцу канала, куда идёт публикация, а не к коду.

## Телеграм-бот

Управление конвейером из чата: прислал ссылку — выбрал пресет и аккаунты — дальше всё само.

**Настройка.** Создай бота у [@BotFather](https://t.me/BotFather), узнай свой id
у [@userinfobot](https://t.me/userinfobot) и впиши в `.env`:

```
SHORTS_TELEGRAM_BOT_TOKEN=123456:AA...
SHORTS_TELEGRAM_ALLOWED_CHATS=123456789
```

Без списка разрешённых чатов бот не запустится: токен рано или поздно утекает,
а бот умеет тратить квоты площадок и публиковать от вашего имени.

**Запуск.** Бот поднимается вместе со всем остальным (`.\scripts
un.ps1`), если
токен задан. Отдельно: `python -m app.bot` из папки `server`. Ключ `-NoBot`
отключает его на один запуск.

**Как пользоваться.** Кидаешь ссылку → бот показывает пресеты кнопками →
показывает аккаунты, отмеченные галочками → «Поехали». Автопрогон включается
сам: ревью в панели не требуется. Аккаунты предлагаются **только те, что уже
заведены на сервере** — вписать чужой нельзя.

Когда проект дойдёт до конца или упадёт, бот пришлёт отчёт: сколько фрагментов
найдено, сколько смонтировано и опубликовано, когда ближайшая публикация по
расписанию. `/projects` показывает, что сейчас в работе.

## Тексты для площадок

Поиск фрагментов уже пишет заголовок и описание, но у него другая задача — отобрать
материал. Отдельная стадия переписывает подпись с расчётом на охват: заголовок,
описание в несколько строк и хэштеги, смешанные по частотности.

Включается в пресете: **Тексты для площадок → Включено**. Там же язык, число
хэштегов, длина заголовка и свободное поле «свои указания» — тема канала, тон,
что упоминать нельзя.

В карточке фрагмента есть кнопка **«Написать заново»**. В автопрогоне стадия
запускается перед публикацией, но по умолчанию **только если заголовка нет** —
чтобы не затирать правки, сделанные руками после ревью. Флаг
«Переписывать перед публикацией» меняет это на «всегда».

## AITunnel

Шлюз к GPT, Claude, DeepSeek и прочим по одному ключу — работает оттуда, где
официальные API недоступны. API у него OpenAI-совместимый, поэтому подключён как
обычный провайдер, отдельного клиента нет.

```
AITUNNEL_API_KEY=sk-aitunnel-...
AITUNNEL_BASE_URL=https://api.aitunnel.ru/v1
AITUNNEL_MODEL=gpt-4o
AITUNNEL_STT_MODEL=whisper-1
```

Дальше `SHORTS_LLM_PROVIDER=aitunnel` — и поиск фрагментов с генерацией текстов
пойдёт через него. Для распознавания речи: `SHORTS_STT_FALLBACK=aitunnel`.
Каталог моделей — https://aitunnel.ru/docs/models

Строгую JSON-схему поддерживают не все модели каталога. Если шлюз её не примет,
запрос автоматически повторится в режиме обычного JSON, а схема уйдёт в текст
промпта — провайдер останется работоспособным.
