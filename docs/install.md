# Установка: панель и воркеры

Панель — пульт: ставит задачи, показывает, что где лежит, управляет парком.
Воркеры делают всю работу: качают исходники, режут, монтируют, публикуют.
Файлы остаются на том воркере, который их сделал.

На одной машине ничего разделять не нужно — `bootstrap.ps1` + `run.ps1`, и всё
работает на SQLite. Ниже — как развести по машинам.

## Что где стоит

| | Панель | Воркер |
| --- | --- | --- |
| Процессы | API, веб-панель, телеграм-бот | `app.queue.worker`, отдача файлов |
| Python 3.10–3.12 | да | да |
| Node.js 20+ | сборка панели | нужен для поставщика токенов YouTube |
| ffmpeg | почти не нужен | обязателен |
| GPU | не нужен | желателен (faster-whisper) |
| Chromium (patchright) | для окна входа в TikTok | для выкладки в TikTok |
| Диск | база и материалы | исходники, нарезка, рендеры — здесь |

## Общее для всех машин

```powershell
git clone <репозиторий> C:\shorts
cd C:\shorts
.\scripts\bootstrap.ps1
```

Скрипт найдёт Python 3.12 (при его отсутствии возьмёт что есть и предупредит,
что локальная транскрипция не соберётся: колёс `ctranslate2` под 3.13+ пока
нет), создаст `.venv`, поставит зависимости сервера и панели, скачает ffmpeg в
`tools\ffmpeg`, поставит Chromium для patchright, соберёт поставщик токенов и
создаст `.env` со свежесгенерированным `SHORTS_SECRET_KEY`.

> **Ключ шифрования на всех машинах должен быть один.** `bootstrap.ps1`
> генерирует свой на каждой машине — это правильно для одиночной установки и
> ломает распределённую. Возьми `SHORTS_SECRET_KEY` с панели и впиши его в
> `.env` каждого воркера **вместо** сгенерированного. Этим ключом зашифрованы
> учётные данные площадок в общей базе и подписаны ссылки на файлы воркеров:
> разные ключи — воркер не расшифрует аккаунты, а панель не покажет превью.

## 1. База: один Postgres на всех

SQLite — файл, к нему по сети не подключиться. Как только воркеры уезжают,
нужен Postgres. Отдельная машина или тот же сервер, где панель.

```sql
CREATE USER shorts WITH PASSWORD 'длинный-пароль';
CREATE DATABASE shorts OWNER shorts;
```

В `postgresql.conf`: `listen_addresses = '*'`. В `pg_hba.conf` — по строке на
каждый воркер, только по TLS и только с известного адреса:

```
hostssl  shorts  shorts  203.0.113.10/32  scram-sha-256
```

Таблицы создавать не нужно — панель и воркер досоздают схему и недостающие
колонки при старте.

Строка подключения одинаковая везде:

```
SHORTS_DATABASE_URL=postgresql+psycopg://shorts:длинный-пароль@db.example.com:5432/shorts?sslmode=require
```

## 2. Панель

В `.env`:

```
SHORTS_DATABASE_URL=postgresql+psycopg://shorts:пароль@db.example.com:5432/shorts?sslmode=require
SHORTS_SECRET_KEY=<этот ключ уйдёт на все воркеры>

# Вход в панель. Пусто — не спрашивается (годится только для localhost).
SHORTS_PANEL_USER=shorts
SHORTS_PANEL_PASSWORD=длинный-пароль

# Ключи площадок и моделей — как в одиночной установке
ANTHROPIC_API_KEY=...
TIKTOK_CLIENT_KEY=...
```

Запуск без воркера:

```powershell
.\scripts\run.ps1 -Prod -NoWorker
```

Панель на <http://localhost:8000>. Наружу — только за HTTPS: basic-аутентификация
шлёт пароль в каждом запросе, это заслон от случайного гостя, а не от атаки.

## 3. Воркер

Скопируй репозиторий на машину, прогони `bootstrap.ps1`, затем в `.env`:

```
# Та же база и тот же ключ, что у панели
SHORTS_DATABASE_URL=postgresql+psycopg://shorts:пароль@db.example.com:5432/shorts?sslmode=require
SHORTS_SECRET_KEY=<скопирован с панели>

# Имя в парке. Меняешь на живой установке — воркер теряет свои проекты и аккаунты.
SHORTS_WORKER_NAME=worker-1
# Адрес, по которому панель заберёт превью и готовые ролики. Нужен ВХОДЯЩИЙ
# доступ: белый IP, проброс порта или туннель. Пусто — задачи идут, превью нет.
SHORTS_WORKER_PUBLIC_URL=https://worker-1.example.com:8770
SHORTS_WORKER_FILES_PORT=8770
# Сколько задач тянуть параллельно
SHORTS_WORKER_CONCURRENCY=2

# Откуда забирать материалы монтажа (маски, баннеры, LUT, шрифты)
SHORTS_PANEL_URL=https://panel.example.com
SHORTS_PANEL_USER=shorts
SHORTS_PANEL_PASSWORD=длинный-пароль
```

Запуск:

```powershell
.\scripts\run.ps1 -WorkerOnly
```

Поднимутся только воркер и поставщик токенов YouTube. Ни API, ни панель, ни бот
не стартуют. Воркер сам зарегистрируется в реестре — через несколько секунд он
появится на странице «Воркеры».

## 4. Проверка

1. Панель → **Воркеры**: воркер на связи, видно, что умеет (`gpu`, `whisper`,
   `browser`), сколько свободно на диске, какой адрес отдачи файлов.
2. Заведи проект — он закрепится за тем воркером, который его загрузил. На
   странице проекта видно, у кого лежат файлы.
3. Открой превью смонтированного ролика. Показалось — значит панель достучалась
   до воркера по `SHORTS_WORKER_PUBLIC_URL`.
4. Загрузи материал (маска/баннер) в «Материалы» и смонтируй ролик с ним.
   В журнале задачи будет строка про скачивание материала с панели.

## 5. Аккаунты площадок

Вход делается **один раз в панели**: «Аккаунты» → «TikTok (браузер)». Слепок
сессии ложится в общую базу, и любой воркер поднимет её сам — профили по машинам
таскать не нужно.

Аккаунт всё же стоит закрепить за воркером (колонка «Воркер» на той же
странице): так публикации одного аккаунта не разъезжаются по разным адресам, а
TikTok резкую смену IP не любит. Аккаунтам на официальных API машина
безразлична — им оставь «любой».

## Порты и направление связи

| Откуда | Куда | Порт | Зачем |
| --- | --- | --- | --- |
| Панель, воркеры | Postgres | 5432 | общая база и очередь |
| Воркер | Панель | 443/8000 | материалы монтажа |
| Панель | Воркер | 8770 | превью и готовые ролики |
| Браузер | Панель | 443/8000 | сама панель |
| yt-dlp | localhost воркера | 4416 | поставщик токенов YouTube |

Единственный входящий порт на воркере — 8770. Не открывается — всё работает,
кроме превью в панели.

## Частые грабли

| Симптом | Причина |
| --- | --- |
| «не удалось расшифровать учётные данные» | `SHORTS_SECRET_KEY` на воркере не такой, как на панели |
| Воркер не появляется в парке | не та `SHORTS_DATABASE_URL` или Postgres не пускает по `pg_hba.conf` |
| Превью не открывается, задачи идут | не задан `SHORTS_WORKER_PUBLIC_URL` или порт 8770 закрыт снаружи |
| Монтаж без маски/баннера, в журнале «не забрал материал» | не задан `SHORTS_PANEL_URL` либо пароль панели не совпадает |
| Задачи проекта висят в очереди | воркер, за которым закреплён проект, офлайн или выключен в панели |
| Публикация не уходит | аккаунт закреплён за офлайновым воркером |
| YouTube отдаёт 403 на загрузку | на воркере не поднялся поставщик токенов (нужен Node.js) |
| Транскрипция уходит в облако | на воркере Python 3.13+ — `faster-whisper` не установился |

## Чего этот способ не делает

- Панель не умеет открыть окно входа в TikTok **на воркере**: канала команд
  «панель → воркер» нет. Окно открывается там, где нажали кнопку. Сессия при
  этом переносится, так что обычно этого достаточно; если нужно войти именно с
  адреса воркера — запусти там `python scripts/tiktok_login.py`.
- Переезд данных из SQLite в Postgres не автоматизирован.
- Basic-аутентификация не защищает от направленной атаки — только HTTPS и
  ограничение доступа по адресам.
